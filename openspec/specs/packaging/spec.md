# packaging 规范

## 目的

定义 NuGet 包的打包和发布规范，确保项目能正确配置、构建和发布到 NuGet.org。本规范涵盖包元数据配置、许可证管理、符号包生成、本地验证流程和自动化发布工作流，为 Csanno 类库的发布提供标准化指导。

## 需求
### 需求：NuGet 包元数据配置
项目必须配置完整的 NuGet 包元数据，确保包能成功发布到 NuGet.org。

#### 场景：包包含必要的元数据
- **当** 开发者构建 NuGet 包
- **那么** 包必须包含 PackageId、Version、Authors、Description、License、ProjectUrl、RepositoryUrl、Tags 等元数据

#### 场景：包有唯一的标识符
- **当** 包在 NuGet.org 上发布
- **那么** PackageId 必须是唯一的且符合命名规范

### 需求：许可证配置
项目必须包含开源许可证文件，并在包元数据中正确引用。

#### 场景：MIT 许可证文件存在
- **当** 用户查看项目根目录
- **那么** 必须存在 `LICENSE` 文件，包含完整的 MIT 许可证文本

#### 场景：包元数据引用许可证
- **当** 用户在 NuGet.org 上查看包信息
- **那么** 必须显示正确的许可证类型和表达式

### 需求：README 作为包描述
NuGet 包必须使用项目的 README.md 作为包的描述页面。

#### 场景：包在 NuGet.org 上显示 README
- **当** 用户浏览 NuGet.org 上的包页面
- **那么** 必须显示格式化的 README 内容

### 需求：符号包生成
项目必须生成符号包（.snupkg）以便用户可以调试源代码。

#### 场景：构建符号包
- **当** 开发者执行 `dotnet pack`
- **那么** 必须同时生成 `.nupkg` 和 `.snupkg` 文件

### 需求：本地打包验证
开发者必须在本地验证包的正确性后再发布到 NuGet.org。

#### 场景：本地测试打包
- **当** 开发者运行打包命令
- **那么** 必须成功生成 NuGet 包且无警告

#### 场景：验证包内容
- **当** 开发者检查生成的包
- **那么** 包必须包含正确的程序集、依赖项和元数据

### 需求：自动化发布流程
项目必须提供 GitHub Actions 工作流用于自动化打包和发布。

#### 场景：触发自动发布
- **当** 开发者创建 GitHub Release
- **那么** 工作流必须自动构建并发布包到 NuGet.org

#### 场景：版本标签识别
- **当** 推送带有 `v` 前缀的标签（如 `v1.0.0`）
- **那么** 工作流必须提取版本号并创建对应的 NuGet 包

### 需求：API 密钥安全
NuGet API 密钥必须安全存储，不得泄露到代码仓库中。

#### 场景：使用 GitHub Secrets
- **当** GitHub Actions 工作流访问 NuGet API
- **那么** 必须从 GitHub Secrets 中读取密钥

#### 场景：密钥不在日志中显示
- **当** 工作流执行时
- **那么** API 密钥必须对日志隐藏
