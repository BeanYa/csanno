# component-registration 规范

## 目的

定义 Autofac 组件的注解式注册规范，通过特性声明实现类型安全、声明式的组件注册。本规范涵盖了组件标记特性、生命周期管理、服务接口映射、构造函数依赖注入、类型过滤规则和错误处理，为 Csanno 类库提供类似 Java Spring 的注解驱动开发体验。

## 需求
### 需求：Component 特性

框架必须提供 `ComponentAttribute` 特性，用于标记类为可注册组件。

#### 场景：标记组件

- **给定** 一个类
- **当** 在类上应用 `[Component]` 特性
- **那么** 该类应被识别为可注册组件

#### 场景：指定服务类型

- **给定** 一个带 `[Component]` 特性的类
- **当** 设置 `ServiceType` 属性
- **那么** 组件应注册为指定的服务类型

#### 场景：添加元数据

- **给定** 一个带 `[Component]` 特性的类
- **当** 设置 `Metadata` 属性
- **那么** 注册时应包含该元数据

### 需求：生命周期特性

框架必须提供对应所有 Autofac 生命周期的特性。

#### 场景：Transient 生命周期

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用 `[Transient]` 特性
- **那么** 每次解析应创建新实例

#### 场景：Scoped 生命周期

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用 `[Scoped]` 特性
- **那么** 在同一生命周期作用域内应返回同一实例

#### 场景：Singleton 生命周期

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用 `[Singleton]` 特性
- **那么** 容器内应始终返回同一实例

#### 场景：PerRequest 生命周期

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用 `[PerRequest]` 特性
- **那么** 在每个 HTTP 请求内应返回同一实例

#### 场景：PerMatchingLifetimeScope 生命周期

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用 `[PerMatchingLifetimeScope]` 特性并指定标签
- **那么** 在匹配标签的生命周期作用域内应返回同一实例

#### 场景：Owned 生命周期

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用 `[Owned<T>]` 特性
- **那么** 应注册为拥有的实例

### 需求：AsService 特性

框架必须提供 `AsServiceAttribute` 特性，用于指定服务接口映射。

#### 场景：指定服务接口

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用 `[AsService(typeof(IInterface))]` 特性
- **那么** 组件应注册为指定接口类型

#### 场景：多个服务接口

- **给定** 一个带 `[Component]` 特性的类
- **当** 应用多个 `[AsService]` 特性
- **那么** 组件应注册为所有指定的服务类型

### 需求：组件注册 API

框架必须提供扩展方法用于注册组件。

#### 场景：注册程序集中的组件

- **给定** 一个 ContainerBuilder
- **当** 调用 `RegisterComponents(Assembly)`
- **那么** 程序集中所有带 `[Component]` 特性的类应被注册

#### 场景：注册调用程序集

- **给定** 一个 ContainerBuilder
- **当** 调用 `RegisterComponents()` 无参方法
- **那么** 调用程序集中所有带 `[Component]` 特性的类应被注册

#### 场景：从类型注册程序集

- **给定** 一个 ContainerBuilder
- **当** 调用 `RegisterComponentsFromType<T>()`
- **那么** T 类型所在程序集中所有带 `[Component]` 特性的类应被注册

### 需求：构造函数注入

框架必须支持通过构造函数自动解析依赖。

#### 场景：单一依赖注入

- **给定** 一个带 `[Component]` 特性的类
- **当** 构造函数包含一个已注册服务类型的参数
- **那么** 解析时应自动注入该服务

#### 场景：多个依赖注入

- **给定** 一个带 `[Component]` 特性的类
- **当** 构造函数包含多个已注册服务类型的参数
- **那么** 解析时应自动注入所有服务

#### 场景：嵌套依赖注入

- **给定** 一个带 `[Component]` 特性的类
- **当** 依赖链中的每个类都有构造函数依赖
- **那么** 应正确解析整个依赖链

### 需求：默认行为

框架必须定义合理的默认行为。

#### 场景：默认生命周期

- **给定** 一个仅带 `[Component]` 特性的类
- **当** 未指定任何生命周期特性
- **那么** 应使用 Transient 作为默认生命周期

#### 场景：默认服务类型

- **给定** 一个带 `[Component]` 特性的类
- **当** 未指定服务类型
- **那么** 应使用类本身作为服务类型

### 需求：生命周期优先级

当存在多个生命周期特性时，框架必须按优先级选择。

#### 场景：优先级解析

- **给定** 一个带多个生命周期特性的类
- **当** 扫描该类
- **那么** 应使用以下优先级（从高到低）：
  1. Singleton
  2. PerMatchingLifetimeScope
  3. Scoped
  4. PerRequest
  5. Owned
  6. Transient

### 需求：类型过滤

扫描器必须只扫描有效的组件类型。

#### 场景：排除抽象类

- **给定** 一个带 `[Component]` 特性的抽象类
- **当** 扫描程序集
- **那么** 该抽象类不应被注册

#### 场景：排除接口

- **给定** 一个带 `[Component]` 特性的接口
- **当** 扫描程序集
- **那么** 该接口不应被注册

#### 场景：排除静态类

- **给定** 一个带 `[Component]` 特性的静态类
- **当** 扫描程序集
- **那么** 该静态类不应被注册

#### 场景：排除无公共构造函数的类

- **给定** 一个带 `[Component]` 特性的类，无公共构造函数
- **当** 扫描程序集
- **那么** 该类不应被注册

### 需求：错误处理

框架必须提供清晰的错误信息。

#### 场景：无效服务类型

- **给定** 一个带 `[AsService(typeof(InvalidClass))]` 特性的类
- **当** 指定的类型不是接口或基类
- **那么** 应抛出 `ArgumentException` 或 `InvalidOperationException`

#### 场景：依赖解析失败

- **给定** 一个带未注册依赖的组件
- **当** 尝试解析该组件
- **那么** 应抛出 `DependencyResolutionException`
