## 新增需求

### 需求：测试目录结构组织
测试代码必须按功能模块组织到独立目录中，每个目录包含相关的测试文件和测试组件。

#### 场景：按生命周期功能组织测试
- **当** 开发者需要查找生命周期相关的测试
- **那么** 所有生命周期测试必须位于 `tests/Lifetime/` 目录下

#### 场景：按元数据功能组织测试
- **当** 开发者需要查找元数据相关的测试
- **那么** 所有元数据测试必须位于 `tests/Metadata/` 目录下

#### 场景：按边界情况功能组织测试
- **当** 开发者需要查找边界情况相关的测试
- **那么** 所有边界情况测试必须位于 `tests/EdgeCases/` 目录下

### 需求：测试组件分离
测试组件定义必须与测试用例文件分离，存放在 `tests/TestComponents/` 目录下。

#### 场景：查找测试组件定义
- **当** 开发者需要查看或修改测试组件定义
- **那么** 所有测试组件必须位于 `tests/TestComponents/` 及其子目录中

#### 场景：测试组件按功能分类
- **当** 开发者需要查找特定功能的测试组件
- **那么** `TestComponents/` 下必须按功能模块（Lifetime, Services, Metadata等）组织子目录

### 需求：共享测试辅助设施
共享的测试辅助类和基类必须存放在 `tests/Fixtures/` 目录中。

#### 场景：使用共享容器构建逻辑
- **当** 多个测试类需要创建 Autofac 容器
- **那么** 必须使用 `Fixtures/` 中的共享辅助方法

### 需求：命名空间一致性
重构后的测试文件必须保持 `Csanno.Tests` 命名空间。

#### 场景：编译测试项目
- **当** 重构后的测试文件编译
- **那么** 所有测试类必须属于 `Csanno.Tests` 命名空间，确保编译通过

### 需求：测试行为保持
重构必须保持所有现有测试的逻辑和断言不变。

#### 场景：运行所有测试
- **当** 执行重构后的测试套件
- **那么** 所有测试必须保持原有的通过/失败状态
